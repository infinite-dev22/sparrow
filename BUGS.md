# Bug ledger

| ID | Symptom | Root cause | Fix | Regression test | Status |
|---|---|---|---|---|---|
| A-001 | Dropdown popup opens without highlighting the option represented by its current value; commit callbacks may run after dismissal. | Floem's `list` creates a separate selection signal initialized to `None`, and `Dropdown::update` dismissed the overlay before invoking the acceptance callback. | Initialize each popup's selection reactively from the controlled value using option identity; invoke chained acceptance callbacks before closing. | `widgets::dropdown::tests::popup_selection_matches_controlled_value`, `open_popup_tracks_programmatic_value_changes`, `popup_reopen_uses_latest_controlled_value`, `selection_is_committed_before_popup_closes`. | Fixed; screen-level scenarios remain unverified. |
| A-002 | Gradle variant selection held a local choice signal separate from the persisted variant. | `variant.rs` copied the persisted string into a temporary `VariantChoice` and synchronized it in a callback. | Use `State.variant` as the shared dropdown's sole controlled value and preserve the label formatting through `dropdown_with_label`. | Covered indirectly by shared controlled-dropdown tests; no Gradle UI scenario exists. | Fixed; integration unverified. |
| A-003 | Run-configuration popup selection depended on array position and did not follow configuration-list changes. | Popup cursor/order used `usize` positions and rows were snapshotted at open. | Use `DapId` for row identity, resolve the active index at activation, and rebuild row/order signals reactively. | `title::run_config_menu::tests::popup_selection_uses_configuration_identity_after_reordering`. | Fixed; visual/keyboard UI scenario remains unverified. |
